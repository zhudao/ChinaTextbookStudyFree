# v1.6.0 发布附件审计与整理

2026-10-25 核对已发布的附件摘要、Web 逐文件清单以及全部 ZIP 的 441,105 个归档条目。机器统计见[审计 JSON](v1.6.0-assets-audit.json)。

## 127 项从哪里来

| 分组 | 数量 | 用途 |
| --- | ---: | --- |
| iOS 数据包 | 51 | 每本教材的题库、正文与图片 |
| iOS AAC 音频包 | 51 | 每本教材按需离线下载 |
| Web、源码与元数据 | 23 | 其中 Web 音频按体积拆为九个 ZIP |
| GitHub 自动源码包 | 2 | ZIP 与 tar.gz 两种获取方式，选一种即可 |
| 合计 | 127 | 用户不需要全部下载 |

实际上传的是 125 个附件，没有摘要相同的整包。未发现 `.DS_Store`、`__MACOSX`、`node_modules`、`.git`、真实 `.env` 或临时部署目录混入归档。

## 有重复，也有待清理资源

- Web 音频共有 47,736 组相同字节的不同路径，重复存储约 2.48 GB（十进制）。主要是历史 `.opus` 文件实际为 MP3，并与后来导出的 `.mp3` 副本相同。直接删一个路径会影响旧页面、源码构建或旧客户端下载；可在后续资源格式中只分发一份，再由安装器恢复兼容路径。
- 当前教材 JSON 引用及其 MP3/Opus 同名资源之外，另有 67,744 个音频文件、约 2.19 GB。这是“当前未引用”，不是安全删除清单；包含历史兼容资源与旧生成候选，需要与旧版本引用及保留策略进一步核对。
- 上述两项可能重叠，不能相加作为可节省体积。iOS 的逐册音频之间还重复约 26.2 MB，目的是每册可独立安装；重复路径的内容一致，没有冲突。
- Web、iOS 和源码包中的正文、图片有用途上的重叠，但分别服务不同安装方式。把 125 个附件全部下载会造成不必要的流量。

## 本次整理

1. Release 首页提供在线学习、Web 安装、iOS 按册下载、源码四个入口。
2. [下载导航](v1.6.0-downloads.md)按安装器实际选择规则列出 Web 下载清单，并将 51 册 iOS 按学科、年级排列，标明新版和旧版。
3. 修正安装文档里过时的 v1.5、Tingting、50 册统计和“下载全部附件”描述。Web 只下载自身需要的包，iOS 只下载所选教材的两包。
4. 现有附件 URL、教材 ID 和成绩数据保留；不将“文件未被当前 JSON 引用”当作删除依据。只更新说明与对应校验元数据。

## 后续减量方案（尚未实施）

新版本采用“主要 Release 提供使用入口，Web 资源与 iOS 资源分别发布”的结构，避免用户直接面对百余个混排文件。需要同步调整安装器、iOS 下载地址和发布校验流程；既有 Release 保留兼容。

Web 资源包可增加内容去重及兼容路径映射，在下载后恢复旧文件名；再按明确的历史版本保留范围剔除失效候选。这会真正减少下载体积。把所有资源塞入一个大 ZIP 只能隐藏文件数量，不能消除重复，还会失去 iOS 按册下载能力。
